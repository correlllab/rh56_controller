# GGX 接入归因审计：2026-09-12

## 结论

**目前不能把低候选获得率直接归因于 GGX。已确认本地执行手型与官方描述不等价；
此外，若干失败标签混合了终态约束、数值搜索不确定性和保守场景模型。**

本轮只诊断，未修改生产代码、手模型、代理、阈值、IK/路径策略、GGX 分数、排名或 top-100。
没有相机采集、机器人连接、手指命令或实机运动。并非为了找通过项而更换手型或碰撞模型。

输入固定为 `reference53_v6_mesh_faces/` 和 `inference_v1/run_04_seed_20260911`；
这是上一轮 top-100 最终为 0 的冻结 mustard 场景。rank 均从 0 开始。

## 1. 坐标和手型：坐标基本一致，生产手型不一致

使用官方 URDF 的 **yourdfpy 独立正运动学**与冻结 MuJoCo 模型比较，不仅做本地转换函数的自我往返验证。

当输入相同关节角时，指节原点最大偏差约 **0.00117 mm**，指节朝向最大偏差约 **0.00045°**。
右手资产与坐标转换的手性一致；手根采用不同轴约定，原始根姿态的 180° 差不能误解为手指整体装反。
YAML 位置读回误差为 0，旋转矩阵元素最大差约 2.37e-7；均值恢复只有约 0.0000298 mm 的浮点误差。
这不支持厘米级平移、左右手镜像或重复加质心是当前主要问题。

但生产路径并没有使用官方相同的关节角：

| 张开状态 | 官方描述 | 本地生产手型 |
|---|---|---|
| 拇指 pitch / intermediate / distal（rad） | 0 / 0 / 0 | 0.1 / 0.283 / 0.216 |
| 食指 proximal / intermediate（rad） | 0 / -0.04545 | 0.025 / 0.025 |

本地来自 `GGX_OPEN_CTRL`、`set_hand_qpos` 的耦合偏置和关节限位裁剪。
在相同 GGX 根姿态下，实际生产张开手型相对官方描述：

- 拇指末节原点相差 **14.215 mm**，末节朝向相差 **34.320°**。
- 以同一个末节局部坐标定义的拇指尖标记点相差 **26.833 mm**；食指标记点相差 **4.955 mm**。
- 同角度比较几乎对齐，说明这不只是不同零位/关节原点相互补偿后的数值差异。

这些是**模型与描述之间的差异**，不是相机测到的真实手指偏差。标记点沿用本地 site 坐标，
不声称官方定义了同名接触点。也尚未确认官方或本地哪一个更接近这只真实 RH56。

官方输出只有抓姿和置信度，没有每个候选的完整关节轨迹；本地张开、闭合策略属于额外接入逻辑。
因此“原始姿态没动”仍不等于“官方手型被原样执行”。

资产限制：冻结快照中的官方逐指 OBJ/GLB 部分仍是 Git LFS 指针，无法据此证明逐指 mesh 完全相同。
整体 `coll_mesh.obj`、缓存 `points.json` 和官方筛选采样点真实存在；这不等于 GGX 用了空几何。

对**过滤器实际使用的完整整体网格**追加最近表面查询：官方 FK 拇指尖标记点距表面约
**0.000058 mm**，本地生产张开拇指标记点距同一网格 **23.710 mm**；食指对应为 0.00120 与 4.164 mm。
这进一步证实手型差异不限于 URDF 文本，但不是完整逐指 mesh 相等性证明，也不是候选碰撞测试。

当前生成器和判别器 checkpoint 实际均选用 `sweep_volume_v2`，手侧条件是官方配置的
12 个 open/mid sweep-volume 参数，并非完整关节手型或原始手点云。
不要把 descriptor、官方过滤器几何和网络实际输入混成同一层。
详细缓存与活动模型输入证据在 `pose_contract/cached_geometry.json`；没有拟合替换参数。

## 2. 57 个目标代理拒绝：不是同一个“零距离”问题

检查保存记录，57 个 `local_approach_unresolved` 都至少包含一个**负距离**，并非纯零值未知。
按首次接触部位确定类别，选该类别原排名最高的固定代表，不用成功率挑样本：

| 类别 | 数量 | 代表 rank | 首次拒绝 | 终态最小查询值（mm） |
|---|---:|---:|---|---:|
| 拇指首先接触 | 35 | 0 | approach | -12.603 |
| 安装件首先接触 | 7 | 9 | approach | -12.850 |
| 其他手指首先接触 | 13 | 11 | approach | -23.999 |
| 局部 pregrasp 已重叠 | 2 | 46 | start | -35.774 |

四个代表使用原冻结代码重算后，局部记录均与原记录完全一致。
它们**在闭合前的最终接近位置也被拒绝**，不只是中间路径不合适；rank 46 的局部起点已经冲突。
这里的 start 是局部 pregrasp 参考起点，不是十点实验的实际远处起点。

对最差/终态几何对，除了 MuJoCo 负距离和 matching contact，还独立进行了凸几何半空间内部见证：
归一化法向后求公共内部点，再直接复核两组不等式和 box 局部坐标。
四个代表均有明确正内部裕量，证明**既有模型中的几何体与 box 代理确实相交**。
该见证只用于诊断，未加入任何执行门禁；内部球半径也不是穿透深度。

这仍不能直接证明真实物体会被撞：目标是保守长方体代理，不是 mustard 的精确实体模型。
在四个选定最小距离几何体的最差帧/终态中，没有找到已观测目标点落入该几何体的证据。
这仅是部分点云上的负证据，**不能证明空间为空或真实无碰撞**，也没有检查所有手指对所有观测点的全路径。

rank 0 的三个正交投影保存在 `collision_v2/rank_0000_endpoint.png`：
灰色是已观测表面，橙色是本地选定冲突几何体，虚线是未改动的 box 代理。
图是投影辅助说明，不能代替三维碰撞证据或物理测量。

四个代表不能代表全部 57 个拒绝已经逐项证明正确。特别是拇指手型契约差异，
仍可能改变接近中的接触先后，但本轮没有切换手型重跑准入来估算“能救回多少”。

## 3. IK 和桌面：必须按实际阶段归因

每类同样取最高原 rank；不增加随机种子、迭代次数或修改容差。

| rank | 保存与复查证据 | 可以得出的结论 |
|---|---|---|
| 3 | 原 16 个数值种子全部失败，最佳位置误差 41.93 mm；重复结果一致 | 终态 IK 搜索未找到解，**不是不可达证明**；尚未尝试接近路径 |
| 31 | 所需腕中心距离 978.94 mm，保守链长界与全部容差合计 945.63 mm | 超出 33.31 mm，属于冻结 CB3 模型下的几何不可达；不是物体碰撞 |
| 1 | 12/16 次终态 IK 成功，得到 5 个不同分支；全部在终态桌面体积检查被拒绝 | 终态约束拒绝，**根本未开始接近路径**；不能按标签误归因为 approach planner 失败 |

8 个 `no_local_approach_solution` 中，7 个的记录只有 `grasp_endpoint` 拒绝；
rank 82 还包含两个分支退到 20 mm 时的数值 IK 失败。生产标签未在本轮修改，只在审计报告中拆开解释。

rank 1 的最近桌面几何对为 wrist_1 或 forearm，均有负 contact；不是零距离分离证书问题。
但必须说明桌面建模条件：当前是保守圆形多边形包络向下延伸 **2 m** 的禁入体积，
XY 包围范围约 **964.5 × 964.5 mm**，不是测量得到的真实桌板尺寸或厚度。
所以 -176 至 -304 mm 是模型查询值，不是“真实手臂穿进桌板这么深”。
桌沿包络的保守程度会限制可行分支，是否产生物理误拒绝仍需独立确认。
